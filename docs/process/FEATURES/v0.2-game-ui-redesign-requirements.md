# Feature requirements: v0.2-game-ui-redesign

**Status:** agreed  
**Owner:** Waldemar  
**Date:** 2026-08-16  

## Goal

Replace the spreadsheet-like hotseat layout with a **tabletop game board** feel: clear scoreboard, icon-led market, readable multi-line action cards, and hover previews of how a card would change each player’s total wealth — without changing game rules.

## In scope

- Fundamental visual/layout redesign of the in-game board (and light pass on setup so it matches)
- Always-visible **scoreboard** for all players: share holdings (by company icon), cash, total wealth
- **Company icons** instead of company name text in market, scoreboard, pickers, and card effect rows
- **Card face layout:** one effect per row (e.g. `2× [BMW icon]` on line 1; `½ [?]` on line 2)
- On `chooseHandCard` (and optionally when inspecting hand), **hover/focus** a card to preview **Δ total wealth** per player
- Keep existing phases, trade rules, and engine behavior

## Out of scope

- Online multiplayer, persistence, AI
- Real trademark logos (use original stylized marks / monograms)
- Price history charts, animations of every tick
- Changing card ops, deck composition, or scoring rules
- Showing other players’ hands

## Users / context

2–4 hotseat players on one device. They need to read the market and their hand as a **game**, compare wealth at a glance, and judge a card before playing it.

## Design direction (visual)

**One composition:** the board reads as a stock-exchange tabletop, not a data admin UI.

| Principle | Choice |
| --- | --- |
| Brand | **Börsenspiel** stays a strong top-of-board signal |
| Mood | Warm trading-floor / felt-table atmosphere (depth, soft vignette) — not flat white panels stacked like Excel |
| Type | Keep expressive display + readable body (existing Syne/Figtree or equivalent); avoid Inter/Roboto/system-only |
| Color | Keep the four company tones; accent stays teal/ink — avoid purple-glow / cream-terracotta / broadsheet clichés |
| Cards | Hand cards remain the interactive “card” objects; scoreboard and market are board chrome, not nested card grids |
| Motion | 2–3 intentional motions: turn highlight, card hover lift, scoreboard wealth flash on preview |

### Layout sketch (desktop)

```
┌─────────────────────────────────────────────────────────────┐
│  Börsenspiel                          [pile]  [New game]    │
├──────────────────────────────┬──────────────────────────────┤
│  MARKET BOARD                │  SCOREBOARD                  │
│  [icon] ▓▓▓▓▓░░░  $120       │  ★ Ada   cash / wealth       │
│         Buy Sell (if trade)  │    CB Bayer BMW BP counts    │
│  …four company tracks…       │  Bob …                       │
│                              │  (current player emphasized) │
├──────────────────────────────┴──────────────────────────────┤
│  TURN / PHASE ACTIONS  (Draw · Trade only · End turn · qty) │
├─────────────────────────────────────────────────────────────┤
│  YOUR HAND  (large card faces; hover → wealth preview)      │
└─────────────────────────────────────────────────────────────┘
```

Mobile: scoreboard collapses under market; hand remains full-width; cards stack.

### Company icons

- Four original marks (letter monogram or simple geometric mark) in the existing company colors
- Accessible: `aria-label` / visible title with full company name on hover/focus
- Used wherever a company is named today in UI chrome (market row, holdings, company picker, card effect rows)
- Card flavor `text` can keep full names (rules copy); **effect rows** use icons

### Card face (effect rows)

Parse/render from `card.ops` (preferred) rather than splitting the title string:

| Ops pattern | Row 1 | Row 2+ |
| --- | --- | --- |
| Named + choice (std / multiplier) | `+40 [icon]` or `2× [icon]` | `−50 [?]` or `½ [?]` |
| +100 style (3+ named) | one row per company op | — |
| Risk | one compact row per company delta (or a 2×2 icon grid of signed deltas) | — |

`[?]` stays a clear choice token (not a fake company icon). Kind badge (action/risk) stays secondary.

### Wealth preview on hover

When phase is `chooseHandCard` and the pointer/keyboard focus is on a hand card:

1. Compute a **preview resolution** of that card’s effects on prices (and share doublings / wipeouts per rules).
2. For ops with `[?]`, preview must still be defined — **recommended default:** show wealth deltas for the **optimistic range** for the current player as primary, and list **per-player Δ wealth** using a **neutral preview choice** (first allowed company) **plus** a note `? = {Company}` — **OR** show min…max Δ per player across allowed choices.  
   **Decision needed in approval** (see Open questions); implementation follows the chosen option.
3. Scoreboard rows show signed diffs next to total wealth (e.g. `+$120` / `−$40`), distinct from live totals.
4. Preview is read-only; it does not mutate game state.
5. Touch: long-press or a small “preview” affordance if hover is unavailable (minimum: focus + visible preview region).

### Scoreboard content

For every player, always:

- Name + “on turn” marker for current player
- Cash
- Total wealth (`netWorth`)
- Share counts per company as icon + number (zeros dimmed)

Replaces the current “Other players” text dump and the per-row “You / Alice / …” owner lines under each price bar (ownership lives on the scoreboard).

## Functional requirements

1. During play (not game over), a **scoreboard** lists all players with cash, total wealth, and per-company share counts shown with company icons.
2. Market rows identify companies primarily by **icon** (+ numeric price); full name available via accessible label / tooltip.
3. Hand **action** cards render **one effect per row** (icon + magnitude / multiplier; `[?]` on its own row when present). Risk cards use a compact icon-led effect layout, not a single dense title string.
4. In `chooseHandCard`, hovering or focusing a hand card shows **Δ total wealth** for each player on the scoreboard (preview), without changing state.
5. Company picker buttons use icons (names as accessible text).
6. Turn / phase actions remain available and obvious; trade Buy/Sell remain on market rows when `canTrade`.
7. Visual redesign must feel like a **game board**, not a spreadsheet (no dense multi-column owner tables; reduced “panel stack” admin look).
8. Engine rules and card catalog ops stay authoritative; UI may add pure preview helpers only.

## Non-functional requirements

- Browser-only; no new runtime dependencies required (SVG icons in-repo are fine)
- Preview helpers are pure functions, unit-tested (TDD)
- Respect `prefers-reduced-motion`
- Works on desktop and narrow mobile viewports

## Acceptance checklist

Human reviews these outcomes (not code by default):

- [ ] Board no longer reads as a spreadsheet; brand + game composition are clear in the first viewport
- [ ] Scoreboard shows every player’s shares (icons), cash, and total wealth
- [ ] Market / holdings / picker / card rows use company icons instead of name-as-primary
- [ ] Cards show separate rows per effect (e.g. `2× BMW` then `½ ?`)
- [ ] Hover/focus on a playable hand card previews Δ wealth per player on the scoreboard
- [ ] Rules behavior unchanged (engine tests still pass)
- [ ] New preview/layout unit tests pass
- [ ] Demo via `npm run dev` (+ short screen capture or notes)

## Open questions

Resolved on approval (design mockup + “do this design”):

1. **`[?]` wealth preview:** (A) min–max Δ across allowed companies; collapse to a single Δ when min === max.
2. **Risk card face:** four-icon signed delta strip.
3. **Ownership under price bars:** removed; holdings live on the scoreboard only.
