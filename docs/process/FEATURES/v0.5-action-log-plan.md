# Implementation plan: v0.5-action-log

**Status:** approved  
**Requirements:** `docs/process/FEATURES/v0.5-action-log-requirements.md`  
**Date:** 2026-08-17  

## Summary

Extract log wording into a small pure formatter module. `reduce()` writes those strings: merge same-company trades in the current session, rewrite the play line as `[?]` ops bind, and emit one Risk line with deltas and resulting prices. The last-drawn Risk banner and Risk card badge reuse the same summary/title.

## Approach

- Keep `GameLogEntry.text` as what the UI shows. Add optional `trade` metadata so merge does not parse strings.
- Same-session merge: scan backward through trailing `trade` entries only; a non-trade line (draw, play, start/end trade, turn) is the session boundary.
- Card plays: log `plays {formatCardOps(card)}` on play; on each `chooseCompany`, update that play entry after binding. Do not append “chooses … for [?]”.
- Risk: drop the extra “draws” + “resolves Risk: title” pair; one line after `applyResolvedCard` using ops + `lastEvents`.

## Steps

1. Add `src/engine/logFormat.ts` with unit tests (card ops, trade merge wording, risk effects including split/wipeout).
2. Extend `GameLogEntry` with optional `trade`.
3. Change `turn.ts` logging as above; update engine tests that pin log text.
4. Point `lastDrawnAnnouncement` at the risk summary; show `card.title` on Risk faces.
5. Run unit tests and `tsc`.

## Out of scope for this plan

- Collapsing “starts trade” / “ends trade” / “Turn →”
- Changing AI trade quantities
- Log UI chrome beyond existing list

## Risks / notes

- Merging by metadata (not regex) avoids brittle parse of older wording.
- Moving an updated trade entry to the end of the array keeps it the newest visible line.
