# Implementation plan: v0.1-hotseat

**Status:** approved  
**Requirements:** `docs/process/FEATURES/v0.1-hotseat-requirements.md` (agreed)  
**Date:** 2026-08-15  

## Summary

Ship a playable hotseat Börsenspiel in the browser: encode the 63-card catalog, a pure rules engine (setup, draw, play, trade, split, wipeout, scoring), a simple React UI, and GitHub Pages deploy. No server.

## Approach

- Card catalog as structured data, not parsed prose
- Engine as pure functions over game state; UI only sends intents
- TDD on engine behaviors before UI wiring
- Vite `base` suitable for GitHub project Pages; Actions publishes `dist/`

## Steps

1. Update `docs/game-rules.md` with digital rulings (split, wipeout, no trade after Action).
2. Scaffold Vite + React + TypeScript + Vitest + lint.
3. Encode all 63 cards.
4. TDD engine: setup pile math, draw branch, `[?]` pick, forbid trade after Action, Risk + optional trade, split, wipeout, scoring.
5. Hotseat UI: new game, market, Draw/Trade, hand, company picker, buy/sell only in allowed phases, game-over ranking; show card text and split/wipeout.
6. GitHub Actions → GitHub Pages.

## Tests first (TDD)

| Behavior | Test idea |
| --- | --- |
| Setup pile math | 2 players → 8 Action in hands, 12 Action + 6 Risk in pile |
| Draw Action | Card joins hand; must play one; trade rejected |
| Draw Risk | Applied immediately; trade allowed |
| `[?]` | Named company fixed; pick must be one of the other three |
| Split | Target 300 → price 150, shareholder shares ×2, bank unchanged |
| Wipeout | Target 5 → holdings 0, bank 40, price 100 |
| Trade validation | Reject overspend / oversell / buy past bank |
| Scoring | Net worth = cash + shares × prices; empty pile ends after resolve |

## Out of scope for this plan

- Online multiplayer, AI, persistence, tutorials, live data

## Risks / notes

- $1,000 start is tight at price 100; that is an agreed rule, not a bug
- After splits, total player shares may exceed the original 40
