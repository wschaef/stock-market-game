# Implementation plan: v0.6-finite-deck

**Status:** approved  
**Requirements:** `docs/process/FEATURES/v0.6-finite-deck-requirements.md` (**agreed**)  
**Date:** 2026-08-20  

## Summary

Switch the engine from recycled cards + round limit to a finite draw pile that ends the game when empty. Setup accepts explicit Risk/Other pile counts with player-count defaults; the start menu drops Rounds and gains those two fields. Rules text and tests follow.

## Approach

- Keep YAGNI: reuse existing `discardPile`; delete round end-path and recycle helper usage rather than adding frameworks.
- Defaults live in a small pure helper (e.g. `defaultPileCounts(n)`) so UI and tests share one table.
- End check lives in `advanceTurn`: if `drawPile.length === 0`, set `gameOver` instead of seating the next player.
- Setup options replace `roundsTotal` with `riskCards` + `otherCards` (names aligned with UI copy).

## Steps

1. **Tests first (TDD):** rewrite/add engine tests for discard-on-play, empty-pile end, setup counts/defaults/validation; update UI default tests; expect round/recycle tests to fail or be replaced.
2. **Types / setup:** remove round constants and `roundsTotal`/`roundsCompleted` from `GameState`; add pile count options; implement defaults + validation; start-log mentions pile sizes.
3. **Turn reducer:** `applyResolvedCard` pushes to `discardPile` (remove `insertAtRandom` use); `advanceTurn` ends on empty pile; drop round-complete logging.
4. **UI:** Setup fields for Risk/Other; reset on player-count change; remove Rounds; HUD shows pile only (no round); wire `setupGame` args.
5. **Exports / fixtures:** clean `index.ts` and test helpers that still set `roundsTotal`.
6. **Rules:** update Digital section in `docs/game-rules.md`.
7. **Verify:** run unit tests; short manual or scripted playthrough with a tiny pile.

## Tests first (TDD)

| Behavior | Test idea |
| --- | --- |
| No recycle | Play Action / resolve Risk → discard gains card; draw pile does not regain it |
| Empty-pile end | Last card drawn and turn finished → `gameOver`; mid-turn after last draw still allows play/trade |
| Setup defaults | For n=2,3,4, omitted counts match defaults table; 4p Other capped at 32 |
| Setup validation | Reject negative, non-integer, empty total pile, over-catalog |
| UI defaults | Player-count change resets Risk/Other; no dependency on `DEFAULT_ROUNDS` |

## Out of scope for this plan

- AI strategy changes (only fixture/type cleanup if required)
- Reshuffling discard mid-game
- Changing catalog inventory

## Risks / notes

- Trade-only turns do not consume cards; ending only on empty pile after a turn that emptied it is required to avoid infinite games.
- 4p default Other=32 already matches catalog leftover; document so UI hint does not promise 36.
