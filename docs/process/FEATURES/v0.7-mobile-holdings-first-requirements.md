# Feature requirements: v0.7-mobile-holdings-first

**Status:** agreed  
**Owner:** Waldemar  
**Date:** 2026-09-26  

## Goal

Cut vertical scroll on narrow viewports by making **all players’ share holdings** the primary board surface, with the **hand in a bottom flyout**, while keeping **one React tree** for mobile and desktop (presentation differs by CSS + minimal open-state).

## In scope

- Mobile-first board density: holdings table (every seat × four companies) always visible without hunting
- Prices shown as a compact row tied to that holdings grid (not four tall bar charts as the only market view on narrow screens)
- Hand cards in a **bottom flyout / sheet** on narrow viewports
- Auto-open flyout when the human **must** play a hand card (`chooseHandCard`); allow peek via a Hand control otherwise
- Sticky / docked phase actions (Draw/Trade, Buy–Sell–End as already required by rules) reachable with the hand dock
- Desktop: same components; holdings remain prominent; hand stays an always-open panel (flyout “stuck open”)
- Preserve existing wealth preview into scoreboard/holdings when inspecting a card

## Out of scope

- Rules / engine changes
- Separate `MobileBoard` / `DesktopBoard` apps or duplicated card/trade logic
- Redesigning setup / game-over beyond light consistency
- New networking, persistence, or AI behavior

## Users / context

2–4 hotseat players (plus AI seats) on one device. On a phone, the human chooses Draw vs Trade and which card / `[?]` / trades by reading **who holds what** and prices — not by scrolling past chrome to find opponents.

## Design direction

**Priority on screen (narrow):**

1. All seats’ share counts + prices  
2. Current player cash / on-turn  
3. Phase actions + hand (flyout)  
4. Secondary: tall market bars, last-drawn detail, action log, helper copy  

**One composition:** one board tree; `@media` (existing ~860px break) switches layout chrome only.

### Mobile sketch

```
┌─────────────────────────────┐
│ Brand · Pile · New          │
│ On turn · cash              │
├─────────────────────────────┤
│ HOLDINGS  CB BY BMW BP      │
│ ★ seats… counts + wealth    │
│ Prices  …                   │
├─────────────────────────────┤
│ [Play] [Trade] [Hand n]     │  ← dock
│ (sheet opens for cards)     │
└─────────────────────────────┘
```

### Desktop sketch

Keep two-column feel: compact holdings/scoreboard + market; hand panel below or in flow, always visible (no forced sheet).

## Functional requirements

1. On narrow viewports, a **holdings grid** lists every player with per-company share counts (icons) without requiring scroll past a full market+scoreboard stack to see opponents.
2. **Prices** for all four companies remain visible alongside or directly under that grid on narrow viewports (numeric; full bar market may be collapsed, secondary, or denser — not the sole tall block above holdings).
3. On narrow viewports, the **hand** is presented in a **bottom flyout**. It **opens automatically** when phase is `chooseHandCard` and it is a human’s turn to play. A control can open/close the flyout when play is not forced.
4. While `chooseHandCard` requires a play, the flyout must not be dismissible in a way that blocks progress (player can still see holdings behind/above the sheet).
5. **Desktop / wide:** same components; hand remains visible as a normal panel (flyout open state ignored or forced open via CSS).
6. Phase actions (chooseTurn buttons; trade controls) stay available and obvious; trade Buy/Sell behavior unchanged.
7. Card wealth preview continues to surface Δ on the holdings/scoreboard rows when a hand card is previewed.
8. Engine rules, phases, and card catalog unchanged.

## Non-functional requirements

- Browser-only; no new runtime dependencies required for the sheet
- Prefer CSS layout variants over forked component trees
- Respect `prefers-reduced-motion`
- TDD for any new pure helpers (e.g. “should hand flyout be forced open?”)

## Acceptance checklist

Human reviews these outcomes (not code by default):

- [ ] On a phone-sized viewport, all players’ share holdings are visible without scrolling past tall market + full scoreboard panels first
- [ ] Hand is in a bottom flyout on narrow; auto-opens when the human must play a card
- [ ] Opponents’ holdings remain readable while choosing a card (sheet does not fully obscure the holdings grid)
- [ ] Wide viewport still shows a usable board with hand always available (no mobile-only dead ends)
- [ ] Rules behavior unchanged (engine tests still pass)
- [ ] New helper tests (if any) pass; lint/tests green
- [ ] Demo via `npm run dev` (+ short notes or capture on narrow width)

## Open questions

Resolved in discussion (2026-09-26):

1. **Opponents first:** holdings for all seats are primary; do not hide scoreboard in a drawer.
2. **Hand:** bottom flyout on mobile; not a second app.
3. **Complexity:** one React tree; CSS + `handOpen` (or equivalent) only.
