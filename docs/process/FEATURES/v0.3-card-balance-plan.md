# Implementation plan: v0.3-card-balance

**Status:** approved  
**Requirements:** `docs/process/FEATURES/v0.3-card-balance-requirements.md` (agreed)  
**Date:** 2026-08-16  

## Summary

Change +100 action cards to **+100 named** plus three player-assigned penalties (**−10 / −20 / −30** on the other three companies, all different), keep **8** such cards (two copies per company), and raise draw-pile actions to **9 per player** (risks stay **3 per player**, risk deltas unchanged). Update rules, engine choice resolution, UI picker, wealth preview, and tests.

## Approach

- Keep existing `deltaChoice` ops; a +100 card carries **three** choice ops (`−10`, `−20`, `−30`).
- Resolve choices **sequentially**: each `chooseCompany` binds the next unbound choice; `allowedChoices` excludes the named +100 company and any already-bound companies; after the third pick, apply all named ops at once (same split/wipeout path as today).
- Single-choice cards (standard / multiplier) keep working unchanged (one `chooseCompany` then apply).
- Wealth preview for multi-choice cards: enumerate distinct assignments of the three other companies to the three amounts (3! = 6) for min/max Δ.
- Pile constant only: `ACTIONS_PER_PLAYER_IN_PILE = 9`. Accept 4p shortfall (32 actions in pile → ~27% risk).

## Steps

1. TDD: catalog shape for new +100 cards; setup pile math for 2p/3p/4p with 9+3.
2. TDD: sequential multi-choice binding and rejection of duplicate companies; single-choice regression.
3. Implement catalog + `ACTIONS_PER_PLAYER_IN_PILE`; extend `turn.ts` choice resolution.
4. Update `cardEffectRows` / UI picker copy (show pending amount); fix `previewCardWealth` for multi-choice.
5. Update `docs/game-rules.md` (+100 text, pile mix, `[?]` multi-assign note).
6. Run lint/tests; short results summary.
